# godb v0.4.0 更新说明

> 从 `v0.2.0` 之后累计 87 个提交，主题是**把「能用」变成「看得见、撑得住」**：
> 存储层补上空间回收与大字段，监控补上图形化的空间侦察与执行探测，
> 控制台补上日常操作的顺手度。数据目录格式（config v4 / meta format 4）与 0.3.0 一致，
> **直接替换可执行文件即可，不需要迁移**。

---

## 一、存储层：删掉的空间能拿回来

| 能力 | 说明 |
|---|---|
| **空闲空间图（FSM）** | 表文件以前只涨不缩、插入只盯表尾。现在记住哪些页有空位，删掉中间的行之后插入会优先复用 —— 「删九成再插回九成」不再让文件翻倍 |
| **大字段外置（`.lob`）** | 超过 2KB 的 TEXT 存进 `tables/tXXXXXX.lob`，行里只留「偏移 + 长度」。单行上限从 4KB 提到 **1MB 以上**，大字段也不再挤占页池 |
| **`VACUUM FULL`** | 整份重写表文件，真正降页数。实测同一张稀疏表：1450 页 / 全表扫描 39ms → **157 页 / 3.0ms** |
| **后台自动整理** | 某张表（≥8 页）删出来的洞超过文件大小 1/4 时，后台最多每 60 秒顺手 `VACUUM` 一次 |
| **页密度 + 空间构成** | 每张表给出「已用 / 空闲 / 洞」三段，并记 `last_vacuum_ms`、`last_vacuum_full_ms`（重启后还在）——「密度 30%」配上「三个月没整理」才是可执行的结论 |
| **坏文件不再当空表** | 数据文件读不出来时明确报错，不再静默返回 0 行 |

## 二、空间地图：从「数字」到「位置」

监控页从一页拆成 **概览 / 诊断 / 存储 / 空间地图** 四页，分类标准是「这一页回答什么问题」：

| 页 | 回答什么 |
|---|---|
| 概览 | 现在健康吗、刚才忙成什么样 |
| 诊断 | 谁在捣乱（慢 SQL / 慢事务 / 锁明细） |
| 存储 | 磁盘够不够、该不该整理（数字） |
| 空间地图 | 东西在哪、长什么样（图形） |

空间地图是这次最直观的一块：

- **矩形树图**：面积正比于**字节**（不是页数、行数），每块底部一条色带标出「数据 / 索引 / 大字段」的构成 —— 一眼看出「六成空间是索引」
- **页网格**：双击进入某张表，逐页铺开，支持 1×～20× 缩放与拖动，20 万行的表也能一屏看完
- **页检查器**：结构 / 文本 / 十六进制三种视图，**直接读文件、不占缓冲池**，不会为了看一眼把热页挤出去
- **关联链**：点一个索引项 → 跳到它指向的堆页那一行 → 再看这一行的大字段（偏移、长度、`.lob` 头的校验结果）

## 三、监控：先给结论，再给数字

- **概览第一块是结论卡**：一句话健康判断 + 三个数字（正在执行 / 等锁+排队 / 最久一条），有事才给「看锁明细」「看慢 SQL」的建议按钮，正常时一个按钮都没有
- **吞吐曲线**：QPS / TPS / 连接数，支持 1 分钟 / 5 分钟窗口切换、暂停刷新
- **存储摘要进首屏**：提交为什么慢最常看 fsync，不该逼人先切页
- **逐表空间表**：索引 / 数据 / 大字段 / 行数 / 页数 / 页密度 / 上次整理，不足 8 页的小表不显示（最后一页天然不满，只会误导）
- 接口分两档：`GET /api/space` 毫秒级（只 stat 文件 + 读 meta），`?table=` 才逐页扫

## 四、执行探测：每一步花了多少

- 新增**执行探测**：按执行序号 1..N 列出每一步的耗时、行数、I/O，回答「服务端 19ms、每一步却 0.5ms，时间去哪了」
- **时间去向**分析：等锁 / 规划 / 执行 / 输出 / 收尾
- 规划耗时单独可见（2026-11 一并修掉了规划偏贵的问题）
- 「计划」入口从结果表头挪到信息栏，当前语句用行号列的竖线标记

## 五、控制台：日常操作顺手度

- 表头**排序** + **拖列宽**
- 侧栏**搜表**
- 结果 **tab 可关闭**
- 历史记录**搜索**与**单条删除**
- 长文本**夹三行** + 点开全文弹窗
- 欢迎页示例 chips、窄屏一套优化
- 去掉工具栏的「美化」按钮（快捷键与命令入口仍在）

## 六、安全与运维

- **登录页**：只对**远程**访问生效，本机打开控制台仍不用登录
- **备份与恢复** + **回收站**：删掉的表能捞回来（`-restore-trash`）

## 七、修掉的坑

- **短事务 / 多语句批次不再从统计里消失**：`txPool` 曾把耗时读数 `0` 当非法值丢弃，加上一个批次只有一个同步点，导致这类事务整条不进统计 —— 这就是之前那次「偶发 FAIL」的根因
- **`TableSizes` 分三段加锁**：不再跨锁读表内字段
- **「值不值得落盘」改用磁盘上的真实字节**，不再按行数估算
- **打开大表只建目录**：20 万行 × 3 列冷启动 7ms，不再解码整表
- 页查找的 `need` 改为向上取整；删掉四处「算了不用」的死代码

## 八、升级说明

| 项 | 情况 |
|---|---|
| 数据目录 | 与 0.3.0 一致（config v4 / meta format 4），**无需迁移**，直接换 exe |
| 备份 | 建议升级前把整个数据目录拷一份 |
| 版本号 | `godb -version` → `godb 0.4.0`；`version()` 报 `PostgreSQL 10.0 (godb 0.4.0)` |
| 产物 | windows / linux / darwin × amd64 / arm64 共 6 个单文件，附 `SHA256SUMS.txt` |
