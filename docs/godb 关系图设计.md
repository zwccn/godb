# godb 关系图设计

> 目标：把「谁引用谁」摊开成一张能读的图。第 1 期（只读 + 自动分组）、
> 第 2 期（拖拽摆位 + 落盘）、第 3 期（手工分组改名换色 + 生命周期剪枝）
> 均已落地，实现细节见第 8 节。

## 1. 定位

页面级视图，和「监控」「设置」同级：顶栏第四个入口，全屏覆盖 `.main`。

不做成侧栏里的一棵树：关系要看的是**整体形状**（几组、谁连谁、谁孤立），
一步步展开的表树恰好把形状藏起来了。

不做成监控面板里的一个 Tab：监控回答「现在跑得怎么样」，关系图回答
「这个库长什么样」，一个是运行时一个是结构，混在一起会让人以为图也要轮询。

## 2. 数据来源

`GET /api/schema` 的每张表新增 `foreignKeys`（出边）：

```json
{"name": "employees_dept_id_fkey", "columns": ["dept_id"],
 "refTable": "departments", "refColumns": ["id"],
 "onDelete": "cascade", "onUpdate": ""}
```

只带**出边**（本表引用了谁）。入边由前端从所有表的出边汇总 —— 同一份事实只在
一处表达，少一处不一致的机会。同时带出 `id`（表 ID），第 2 期落盘布局时要用。

## 3. 自动分组

用外键的**连通分量**（并查集）分组：A 引用 B、B 引用 C，三张表就是一组。
自引用（`org.manager_id → org.id`）不参与合并。

组内上下顺序用**松弛**而不是拓扑排序：外键成环（a↔b）在真实库里存在，
拓扑排序会失败；松弛迭代「子 = 父的深度 + 1」，跑表数轮上限就停，能收敛到
「尽量分层」。被引用的表在上，引用别人的在下。

孤立表单独成一组「未分组」，永远排最后 —— 它们没有连线，混进关联组只会更乱。

组标题用组里前两张表的名字拼（`departments · employees +2`）。自动分组没有语义
信息，硬起一个「人事域」只会猜错；等手工分组做出来，名字才是用户给的。

## 4. 布局与连线

- 卡片宽 236，标题栏 28，每行 20，卡片间距 26；组框 = 内边距 18 + 左侧走线通道 18。
- 组与组横向排，超过 1480px 换行。
- **上下相邻就连直线**（父在下边框 → 子上边框）。这是最常见的情况，拐弯反而看不出
  它们直接相连。
- **隔着卡片就连不上直线**：走组框左侧的通道绕过去，从子卡片的「外键列那一行」
  出发，到父卡片的「被引用列那一行」进入。多条边共用通道时依次错开 5px。
- 端点标记：子端画鸦爪（三条短线），父端画一条短横线「一」。短横线画在卡片**外面**
  3px 处 —— 连线层在卡片下面，压在卡片里会被盖掉。
- 悬停卡片：点亮它参与的连线与两端卡片。表一多，光靠颜色找一根线比找针还难。

## 5. 分组色

8 个色相固定（262 紫 / 168 青 / 20 珊瑚 / 330 粉 / 212 蓝 / 92 绿 / 38 琥珀 / 220 中灰），
**明度与透明度交给皮肤**：

```css
:root { --er-tint: .20; --er-line: .45; }
html[data-theme="sky"], [data-theme="taro"], [data-theme="mint"] { --er-tint: .13; --er-line: .52; }
```

原因很实际：8 个色相 × 6 套皮肤各写一遍就是 48 个值，调一次要改一整天；而且深色皮肤
上 alpha 小了看不见，浅色皮肤上同样的 alpha 会扑成一块脏色。组名一律用 `--text`，
不让色相参与文字色 —— 那是最容易在浅色皮肤上掉对比度的地方。

## 6. 交互

| 操作 | 行为 |
|---|---|
| 顶栏「关系图」/ Esc | 打开 / 关闭 |
| 滚轮 | 以光标为锚点缩放（0.15×~2.5×） |
| 拖空白处 | 平移 |
| 点卡片 / Enter | 关面板 + 打开这张表（和侧栏点表名同一个动作） |
| **拖卡片** | 摆位置；位移超过 4px 才算拖，松手落盘 |
| **双击组标题** | 就地改名（Enter 提交 / Esc 取消 / 失焦提交） |
| **点组色点** | 8 个色相循环切换 |
| **自动排列** | 清掉手工坐标、回到按外键推出来的位置；组名和颜色保留 |
| 适应画布 | 缩放到刚好放下；上限 115%（表少时放太大反而空） |

打开时总是重新适应画布：关了再开还停在上次的奇怪位置，会让人以为图没刷新。

**点卡片和拖卡片共用一个 pointer 序列**，在 `pointerup` 里按位移分流，不用 `click`：
拖动结束时浏览器照样补一个 `click`，两个行为抢同一个事件只能靠「刚才拖过没有」
这种标记区分，很容易漏复位 —— 表现成「拖完一张表，下一次点别的表没反应」。

拖动过程中只改卡片的 `left/top` 和组框尺寸，连线淡到 25% 不重算：每帧重建整张图
会丢 pointer capture，手一快就变成「拖到一半卡片卡住」。松手才 `erRender()` + 落盘。

最近拖过 / 改过的那一组排到最后画（`erHotGroup`）：DOM 顺序就是层级，卡片拖到
别组旁边时如果还沉在下面，会被别人的卡片盖住 —— 明明是正在摆的那张，却看不见。

## 7. 已知边界

- **没有外键的库只有孤立卡片**：底部给一条提示条，说清「建表时写 REFERENCES 再来」。
  这是最常见的状态（建表时大多数人先不写外键），不给提示会以为功能坏了。
- 卡片最多显示 14 行字段，多了折成「还有 N 列」；卡片折叠还没做。
- 表超过约 60 张会拥挤，还没做分组折叠。
- **分组只能改名和换色，不能手工改成员**：成员由外键连通分量推导。想把一张表
  挪进别的组，得先有那条外键（或者接受它留在原组）。改成员需要一套「组框是固定
  矩形、拖进去就归组」的交互，比现在这套「框跟着卡片长」重一档，留到以后。
- **组框只包住「抱团的那一簇」**（`erBoxMembers`，相邻判定 3 个卡片间距）。把一张
  卡片拖远之后它不再撑框 —— 否则框会变成一个空荡荡的巨框，把路过的别组卡片一起
  框进去，看图的人会以为那些表也属于这一组。拖出去的那张仍然属于原组（颜色不变，
  可以再拖回来）。
- 「表设计器」的「引用（外键）」列只能编辑**单列外键**；复合外键会保持原样并在
  预览里给一句说明（引擎的 `ALTER TABLE ADD FOREIGN KEY (a,b)` 是支持的，界面上
  还没做多列选择）。

## 8. 实现记录（第 2、3 期）

### 8.1 侧车文件

布局放 `<数据目录>/diagram.json`，每个库一份（多库各自一套目录，天然隔离）。
**不进 catalog.json**（那是 schema 的唯一真相，会被 DDL / 备份 / 回收站 / PG 兼容层读），
**不进 localStorage**（换浏览器就丢，图属于库不属于浏览器）。

```json
{"version": 1,
 "cards": {"2": {"x": 252, "y": 73}},
 "groups": [{"id": "gmw27lf47lyd0", "name": "组织架构", "color": 3, "tables": [5, 6]}]}
```

几个和最初设想不同的地方：

- **`color` 是 0..7 的数字，不是 `"purple"`**：色相本来就固定在 8 个上，用数字直接
  对应 CSS 的 `g0..g7`，省一层名字映射。`-1` 表示「跟随自动配色」。
- **没有 `view`**：缩放和平移每次打开都重新适应画布（见第 6 节），存了反而要处理
  「布局变了但视口没变」这种对不上的状态。
- **键是表 ID，不是表名**：RENAME 之后布局要跟着那张表走。ID 只增不复用，所以
  DROP 掉的老 ID 永远不会被新表占用 —— 剪枝时按「当前 ID 集合」对账是安全的。
- **组名最多 40 字**，超了截断；空 id / 重复 id 的组直接丢掉（改 id 会让前端的旧
  引用全对不上，不如丢）。

### 8.2 接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/diagram` | 读布局，按当前表**剪枝**后返回 |
| POST | `/api/diagram` | 整份覆盖（清洗 + 剪枝 + 原子写） |

**整份覆盖而不是增量**：一张图的坐标是相互关联的（拖走一张，旁边那张的位置才有
意义），增量更新反而要处理更多冲突。拖动松手时前端把**所有**卡片坐标一次性存下来，
不是只存被拖的那张 —— 只记一张的话，剩下的下次打开会按自动布局重排，等于拖了个寂寞。

读失败 / JSON 坏掉一律当「没有布局」：关系图是锦上添花的视图，不能让一个坏文件
把整张图变成打不开的错误页。写入走 `tmp + fsync + rename`（和配置文件同一套）。

进门先归一化，不信任何一条坐标：NaN / Inf / 超过 ±100000 的坐标会让画布撑到浏览器
算不出来的尺寸，表现成「打开就白屏」，比报错还难查。

### 8.3 生命周期

| 事件 | 行为 |
|---|---|
| RENAME TABLE | 原位不动（键是 ID） |
| DROP TABLE | 下次 GET 时按 ID 剪掉坐标；成员被剪空的组整组删除，并写回文件 |
| CREATE TABLE | 自动分组接住；手工摆过位的话，新卡片排在已有内容下方一行 |
| 清空库 / 载入示例 | 同上，全部剪光（文件只剩 `{"version":1}`），不需要专门清理 |

剪枝放在**读**的时候做，不挂在 DDL 上：DROP 的时候没人会想到去通知这张图，等下次
打开关系图时按当前 catalog 对一遍账最省事，也不会让 DDL 多一条失败路径。

### 8.4 手工分组怎么和自动分组共存

`diagram.json` 里的组是**覆盖**：属于手工组的表先被认领，剩下的表再走连通分量。
好处是新表仍然会自动找到位置，而「我改过名字的那组」不会因为多了一条外键就被
重新洗牌。

自动组只在用户**真的改了名字或颜色**时才升级成手工组 —— 「双击看一眼、直接回车」
不该产生任何副作用，否则这一组从此就固化了，以后加外键它不再跟着重排，用户会
觉得图变呆。

### 8.5 回归覆盖

`tools/ui_check.js` 里关系图部分用**真实鼠标**（`Input.dispatchMouseEvent`）走完
拖动 → 落盘 → 重开 → 自动排列 → 改名 → 换色 → 点卡片打开表这条链路，最后清空
侧车文件。断言全部用**模型坐标**（`style.left/top`）不用屏幕坐标：每次打开都重新
`erFit`，缩放不一样，屏幕坐标比不出结论。

跑之前先清一次 `diagram.json`：不清的话「自动排列摆回原位」拿的基准是上次的残留
位置，这条断言会时好时坏。服务端的清洗/剪枝另有一套 Go 单测（`web/diagram_test.go`，
4 个用例覆盖空文件、往返、DROP 剪枝、坏数据归一化）。

## 9. 样例数据

关系图要有东西看，示例库就得有外键。`db/sample.go` 现在多了：

- `employees.dept_id REFERENCES departments(id)`
- `orders.employee_id → employees.id`、`order_items.order_id → orders.id`（三级链）
- `tags.article_id → articles.id`

载入示例数据后打开关系图：6 张表 / 2 组 / 4 条外键。
注意已有的库不会自动获得这些表 —— 改动只对「载入示例数据」之后生效。
