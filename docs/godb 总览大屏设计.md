# godb 总览大屏 · 设计说明

> 打开控制台第一眼看到的那一页。`web/assets/index.html` 的 `#homePanel`，
> 逻辑在 `app.js` 的 `renderHome` 一屏，样式在 `style.css` 的 `.home*` 段。

## 1. 它回答的问题

数据库大部分时间都在安稳运行。这时候需要的是**「现在能不能走开」**，不是一堆指标。

所以这页不是监控面板的缩水版，两者回答的问题不一样：

| | 总览 | 监控 |
|---|---|---|
| 回答 | 现在能不能走开 | 出事了，是谁在挡谁 |
| 呈现 | 一个结论 + 六个数字 | 锁明细 / 慢 SQL Top10 / 页地图 / 按表聚合 |
| 正常时 | 安静：同一种白，大片留白 | 满屏彩色，因为它就是用来看异常的 |

由此推出三条硬约束：

1. **没事的时候看起来是安静的** —— 只有异常那一格才变色。
2. **数字要大**，远看或瞄一眼就能读；单位小一号、灰一档，不抢数字。
3. **一屏不滚**，任何需要滚动的都不属于这里。

## 2. 四层结构

```
┌ 状态条 ─ dot · 库名 · 版本 · 健康/有排队/已触顶 ─ 已运行 · 时钟 · 详细监控 ›
├ 六个数字 ─ QPS · 排队 · 等待锁 · 执行中 · 内存 · 带宽
├ 两条走势 ─ 吞吐（QPS / 连接 / 带宽）        资源（内存 / CPU）
└ 结论条 ── 「没事，可以走开」+ 累计慢 SQL / 连接 / Kill
```

六个数字的**顺序不是随手的**，眼睛从左往右读就是一条推理链：

- **QPS** 是业务量基准：现在有多少请求
- **排队 / 等待锁 / 执行中** 是同一条执行流水线的三个位置，加起来就是「系统现在有多少活、卡在哪」。
  顺序按**一个请求的行走路线**排：先排队等执行槽位，拿到槽位再等锁，最后才真正执行 ——
  执行中是这条线的**末端**，放在最前面会把因果读反（看起来像「先执行、再排队」）
- **内存 / 带宽** 是资源：机器扛不扛得住

状态条只说状态（健康 / 有排队 / 已触顶），判断和建议放底部一条 ——
两处都写「运行正常」等于占两次地方。

## 3. 固定深色

`.home` 自带一套 `--hm-*` 变量，**完全不读 `--bg` / `--text`**。

这是六套皮肤之外的**故意例外**：科技感来自深底亮数字的对比度，浅色皮肤下做不出来；
大屏又常挂着看，深色不刺眼。切皮肤时这一页不变。

代价要认：它是唯一不跟随皮肤的页面。改配色时改 `--hm-*`，别去动全局变量。

## 4. 数据来源

全部来自 `/api/monitor`（`db/activity.go` 的 `Monitor` 快照），**不新增接口**。

- 轮询复用 `pollMonitor`：全局 2 秒一次，总览和监控各画各自的 DOM。
  同一份快照画两页，数字必然一致；任一页开着也只有一路轮询。
- 数字只在**变了**才写 `textContent`：每 2 秒重写六个同样的字符串会让六格一起闪，
  而大屏是挂着看的。
- 时钟单独 1 秒一跳：跟着 2 秒轮询走的话秒数会一次跳两格。
- `startedAtMs` / `version` 由 `web/monitor.go` 注入（匿名嵌入进返回体，不多发请求）。
  进程启动时间是包级变量 —— 运行时长是**进程**的属性，多库共用一个进程。

## 5. 带宽怎么算

这是这页唯一需要动后端的指标。

### 5.1 统计点在 listener 层

`netio` 包（`netio/netio.go`）把 `net.Conn` 包一层，`Read` / `Write` 各挂一个
`atomic.Int64`；`netio.Wrap(ln, c)` 返回的是包装过的 listener，`netsrv` 在
`rebindPG` 里只包 PG 那一路。

两个关键选择：

- **包在 TLS 之外**：加密连接记的是上线缆的字节数，那才是「带宽」；
  记明文长度会少算 TLS 记录头和 padding。
- **只统计 PG，不统计 HTTP**：控制台自己每两秒轮询一次 `/api/monitor`，
  算进去会得到一个恒定底噪，把真正在做的事埋掉。

计数器是**进程级、只增不减**（`netio.PG`）：调用方靠两次采样求差算速率，
中途清零会算出负数；热切换端口也不用重置，换了监听接着累加，差值仍然对。

> 为什么是包级全局而不是挂在 DB 上：带宽是「这台机器在往外吐多少数据」，
> 多库共用一个监听端口，分摊到库没有意义。也因为 `db` 要读它、`netsrv` 要写它，
> 而 `netsrv` 已经 import `db` 了，只能挪到一个两边都依赖的叶包里。

### 5.2 收 / 发分开

`RatePoint` 多了 `netIn` / `netOut`（每秒增量），`RateStats` 多了当前值（5 秒平均）
和峰值。分两条而不是加总：**查大结果集时发远大于收，灌数据时反过来**，
合成一个数就看不出「是在拖数据还是在灌数据」。

大屏那一格显示的是合计，副标题拆开写 `↓收 … · ↑发 …`；
吞吐曲线里也是合一条 —— 两条几乎重合的线反而看不清，要精确对比去监控页。

### 5.3 首点只立基线

和 QPS 同一个约定：`thruPos > 0 || thruFilled` 才算差值。第一次采样必须记 0，
否则会把「进程启动至今」的所有字节当成这一秒。没采到第二个点之前显示**破折号**，
不是 `0 B/s` —— 0 会被读成「真的一点流量都没有」，那是另一回事。

## 6. 曲线

`homeChart()` 一个函数画两条卡片，每条线**各自归一化**，另按 `minSpan` 撑开：

- QPS 几百、连接数几，共用一根轴会把连接数压成贴着底边的直线，等于没画。
- 内存只在几 MB 内浮动，逐像素归一化会把噪声放大成过山车，看着像要炸了。

代价是看不出两条线谁高，所以底部图例直接报当前值。

窗口与监控页一致：每秒一个采样点、最近 5 分钟、同一个 300 点环形缓冲。

## 7. 入口

顶栏拆成两个：**总览**（`#btnOverview`）与**控制台**（`#btnHome`，原来的「首页」
其实是「回编辑器」）。

- 打开控制台默认落在总览；
- `#console` 深链直接进编辑器 —— 给自己存书签用，也是回归脚本的入口
  （三百多条断言都假设编辑器在前台，全改成「先点控制台」既啰嗦又容易漏）。

## 8. 回归覆盖

`tools/ui_check.js` 末尾 12 条（这一段必须放在最后：它会导航到不带 `#console`
的地址，中途跳会把前面所有依赖编辑器的断言带红）：

默认落地 → 六个数字 → 两个 Tab 二选一 → 执行/排队/等锁与接口一致 → 健康灯
→ 两条曲线 → 带宽格带 `/s` 且拆收/发 → 吞吐曲线真是三条线 → 版本/运行时长/时钟
→ 结论条判断 → 进监控时总览让位。

带宽的计数逻辑单独在 `netio/netio_test.go`（收发分别计、listener 包装、
Close 透传、只增不减）和 `db/rates_test.go`（首点立基线、空闲的一秒必须是 0、
峰值与 5 秒平均）。

## 9. 已知取舍

- **超宽屏底部留白**：2400×1200 下内容铺到约 2/3 处，底部 ~20% 是空的。
  试过让曲线撑满，一条 QPS 会被拉成心电图；试过把结论条贴底，空白就跑到中间去，
  更难看。现在的选择是「内容靠上、底部留白」，1080 高下不明显。
- **监控页暂未单列带宽**：那张「吞吐与连接」卡是三格网格（`repeat(3, 1fr)`），
  加第四格会独自占一整行。数据在 `/api/monitor` 里已经有了，要加得先改网格。
- **只统计 PG**：WebSocket / HTTP 的流量不进这个数，见 5.1。
