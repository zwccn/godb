# godb 模型图设计

> 目标：一张**由人说了算**的逻辑模型图 —— 表怎么归类、谁和谁有关、关系是一对一还是一对多。
> 图是源头：它不读外键，也不反推；库里有没有那条约束，与这张图无关。
>
> **2026-11 更新**：表已经不再来自 `schemaCache`，而是来自「模型」这个独立对象
> （自带表、列、类型，可以脱离库存在、可以定版）。本文讲画布本身的交互与几何；
> 模型怎么存、怎么定版、怎么迁移，见《godb 模型与版本设计.md》。
> 文中提到 `diagram.json` 的地方，现在由 `models/<id>/model.json` 承担。

## 1. 定位：逻辑图是源头，物理图是第二阶段

上一版把「逻辑视图 / 物理视图」做成一对可切换的视图，逻辑层还能显示出外键（实线）、
手工关系（虚线）、折叠的关联表。这让图**同时**在回答两个问题：我理解的模型是什么、
库里到底有什么。结果两边都答不好：

- 逻辑图上一条实线，用户得先想「这是库里有约束还是我画的」，才敢照着写 SQL；
- 一条虚线画得再清楚，也没法表达「我认为这里是 1:1」——因为它的语义已经被
  「库里没有约束」占用了；
- 折叠纯关联表（`article_tags`）是**从外键结构推出来的**结论，本质上还是在读库。

所以这一版把范围收死：

| | 现在的模型图 | 第二阶段才做的物理图 |
|---|---|---|
| 关系的来源 | **只有人画的** | 库里真实的外键 |
| 基数 | 1:1 / 1:N / M:N 三种，人说 | 从唯一键推导 |
| 连线 | 字段 → 字段，线指到具体行 | 字段 → 字段 |
| 库里写着外键 | **图上一条线也不画** | 一条不少 |
| 折叠关联表 | 不做 | 不做（谁想折叠自己收起那张卡片） |

**为什么连「库里有约束」都不标**：一旦标了，图就必须跟着库变 —— 加一个外键，
图自己长出线来；删一个外键，线自己消失。那它就不是模型了，是 schema 的投影。
现在这张图的每一条线都是有人按了一次鼠标才存在的，图上多一条、少一条都有人负责。

**不做反向推导**：没有「从外键导入关系」的按钮，也没有「首次打开自动播种」。
已经写了 `REFERENCES` 的库第一次打开模型图是**完全空白的 6 张卡片、0 条线**，
用户得自己从字段拉出来。这一步看着笨，但它是「以逻辑图控制物理图」的前提 ——
第二阶段要拿逻辑图生成 DDL 时，图上的每条关系才都有明确的来处。

## 2. 数据来源

`GET /api/schema` 提供表、列、行数，**只用来画卡片**：

```json
{"name": "er_fact", "id": 6, "rows": 12,
 "columns": [{"name": "basis_id", "type": "integer"}]}
```

`foreignKeys` / `uniqueKeys` 字段接口还在（表设计器、PG 兼容层在用），但模型图
**一个都不读**。这是一条纪律，不是疏忽：读一个字段，就会有人给它加一个用途。

## 3. 分组：用户划的，不猜

早先的版本按外键连通分量自动分组（A 引用 B 就把它们并成一组）。这个做法错在把
**「谁引用谁」当成了「谁和谁是一类」**：`orders.customer_id → customers`，但订单属于
「交易」、客户属于「客商」——它们必须分在两组，同时有连线。跨组关系是常态，不是例外。

所以分组是用户建的一等对象：

- 没建组 → 全部进「未分组」（虚拟组，不能改名换色，永远排最后，不落盘）
- 建了组 → 空组也画出来，否则「新建分组」看起来毫无反应
- 一张表只属于一个组，归属由 `tables[id].group` 决定，不由「组里列了谁」决定

组内上下顺序按**画出来的关系**推：From 端在上、To 端在下（`1N` 的「一」侧在上）。
用**松弛**而不是拓扑排序 —— 关系成环（a→b→a）在真实模型里存在，拓扑排序会失败；
松弛迭代「子 = 父深度 + 1」，跑表数轮就停，能收敛到「尽量分层」。`M:N` 不参与分层：
两端对称，强行分层会把它们拆成上下两层，看着像有方向。

## 4. 关系：只有一种来源，三种基数

```json
{"id": "m9x1", "from": {"table": 4, "columns": ["id"]},
              "to":   {"table": 6, "columns": ["basis_id"]}, "card": "1N"}
```

| 字段 | 含义 |
|---|---|
| `from` / `to` | 两端都是**表 + 列**，不是表 |
| `card` | `11` / `1N` / `NM`，**从 from 看向 to** |

### 4.1 方向是有语义的

`card = 1N` 读作「**from 端是一个，to 端是多个**」。这不是显示习惯，是数据：

- 画符号：from 端画一横，to 端画鸦爪；
- 第二阶段生成 DDL 时，`to` 才是子表（外键写在 `to` 的列上，指向 `from`），
  所以方向必须留得住，不能靠「屏幕上谁在左边」临时猜。

拖线时松手弹的菜单里就有 `N : 1 · 起点多个、终点一个`，它做的事是把两端交换后存成
`1N` —— 用户说的「一道多」，落到存储里永远是「一道多」这一个形状。

### 4.2 一条关系只连一对字段

同一对字段只能有一条关系，**正反都算**（`erLinkCovers` 比对时两个方向都查）。
允许重复的话，图上会出现两条完全重合的线，点其中一条改基数，另一条还是原样，
用户没法判断哪条才算数。

复合关系（多列对多列）**结构上允许**（`columns` 是数组，`normalize` 校验两端列数
必须相等），但 UI 只给单列 —— 弹窗是单选，拖线也只认一行。复合外键真要做，
改的是弹窗，不是侧车格式。

### 4.3 自连接是合法的

`employees.manager_id → employees.id` 是同一张表的两列。归一化时丢掉的是
**同表同列**（自己连自己，一条零长度的线，没有任何意义），同表不同列保留。
自连接的线从卡片右侧出、绕回来落在同一张卡片的不同行上。

## 5. 画线：线要指到字段上

### 5.1 端点落在字段行

起止点 y = `card.y + headH + rowIndex * rowH + rowH / 2`，正好是那一行的垂直中心；
x = 卡片左/右边缘。这就是 DbSchema 那种画法：**能看出接的是哪一列**，
而不是「这张表连那张表」。

找不到那一列时（列被 ALTER 掉了、还没剪枝到）端点退回**卡片中心**，不退到第一行 ——
落在第一行是在骗人说「接的就是这一列」。

### 5.2 出线侧与通道

`erEdgeSides` 定两端各从卡片的哪一侧出（`+1` 右 / `-1` 左），抽成独立函数是因为
**分配通道和画线两处都要用同一个判断**，各算一遍迟早算出两种结果，线就会从一边出、
往另一边绕。

- 两卡左右分开 → 对着出（a 右、b 左），中间那段竖线走两卡之间的缝；
- 两卡上下叠着（水平投影相交）→ 都从右侧出，竖线绕到两卡右侧最外那条通道。

**通道错开（lane）**：同一侧的线按序号错开 `laneGap: 7`。一列卡片右侧往往同时有
三四条线，全挤在同一个 x 上会合成一根粗线，看不出哪条接哪行；错开之后平行下去，
像盘线一样一眼能数清几条。端点符号跟着错开同样的距离，否则两个鸦爪会叠成一个
看不懂的记号。

### 5.3 绕开别的卡片

左边一组连右边一组时，**中间那组就挡在路中间**。原来直接取两端中线当通道，竖线会
穿进中间那组的卡片里 —— 卡片画在连线上面（DOM 顺序），看起来是「线进了这张表又从
另一边出来」。更糟的是两端恰好都在第 0 行时，线会正好压在对方 `id` 那一行上，
被误读成「这条线接的是这一列」。实测就撞上了这种情况。

所以通道和横线的位置都不固定，由三个小函数现挑（候选值只取**卡片边缘内外 11px**，
绕行的最优解一定贴着某张卡片的边，中间随便取点没有意义）：

| 函数 | 挑什么 | 用途 |
|---|---|---|
| `erBlocksInCol` / `erBlocksInRun` | 这段竖线/横线压到卡片没有 | 判定（4~5px 容差：贴着边走是正常的） |
| `erFreeRunX` | 竖线走哪一列 | 从两端中线出发，撞上就挪到卡片外侧、离中线近的那边 |
| `erFreeRunY` | 横线走哪一行 | 同上，但只在这条横线的 x 范围内找 |

竖线变长之后可能又压上别的卡片，所以按新的两端再校一轮。**绕太远就不绕**：
`|ya-ay| > 220` 时退回直连 —— 一条横穿整张图的长线比「从卡片背后穿过去」更难看，
也更容易看错。

`ui_check.js` 有一条断言钉住这件事：把每条连线的 path 按 4px 采样，落进任何一张
「非两端」卡片的内部就算失败。

### 5.4 直角折线 + 圆角

`erPolyPath(pts, r)` 用 `Q` 二次贝塞尔把每个折角切成 7px 圆角。不再用三次贝塞尔曲线：
曲线看着柔，但它**不告诉你线要往哪绕** —— 两卡之间只有 64px 缝的时候，曲线会
擦过对面的卡片，而且相邻两条曲线几乎一定交叉。折线 + 通道是可预测的。

### 5.5 基数符号

画在卡片**外面** 3px（连线层在卡片下面，画进去会被盖掉）：

- 「一」= 垂直于线的一根短杠；
- 鸦爪 = 三条线从线上一点（离卡片 10px）发散到卡片边缘，三个终点落在同一行上，
  看着像爪子扒住这个字段。反过来画（终点散开、根贴卡片）会变成一个悬空的「人」字。

`NM` 两端都是鸦爪，`11` 两端都是短杠。

## 6. 布局

`ER` 常量（`web/assets/app.js`）：

| 项 | 值 | 用途 |
|---|---|---|
| `cardW` / `headH` / `rowH` | 236 / 28 / 20 | 卡片宽、标题高、每行高 |
| `gap` / `colGap` | 26 / 64 | 同列卡片间距、列间距 |
| `groupPad` / `groupHead` / `groupGap` | 18 / 30 / 46 | 组框内边距、标题条、组间距 |
| `chanW` | 44 | 组框左侧走线通道 |
| `stub` | 20 | 出线后先横走一段 |
| `laneGap` / `corner` | 7 / 7 | 通道间距、折角圆角 |
| `maxRows` / `colH` / `rowMax` | 14 / 820 / 1520 | 卡片最多几行、目标列高、组横排上限 |

- **组内分列**：按「总高度 / 820 得到目标列数，再均分成员」，不是固定每列几张。
  卡片高度差得很多（3 列和 12 列差一倍），按张数分会一列很长一列很短。
- 组与组横向排，超过 1520px 换行。**组框宽度必须和自动布局预留的宽度一致**
  （`2×groupPad + chanW + 内容宽`），否则间距会被吃掉：以前 `erRelayoutBoxes`
  左右各加一个 `chanW`，框比预留宽 44px，46px 的间距只剩 2px —— 看着就是「组挨在一起」。
  `chanW` 是**左侧**走线通道，右边只留内边距。
- 空组没有卡片，框是定死的「一张卡片宽 + 内边距」，自动布局要按同一个尺寸占位；
  它的位置也只存在组记录里，所以**自动排列必须连 `groups[].x/y` 一起清**，
  否则空组留在拖动后的原地，新布局排过来正好压在它身上。
- `maxRows: 14`：卡片最多显示 14 行，多的折成「还有 N 列」。卡片本身不折叠。

## 7. 交互

| 操作 | 行为 |
|---|---|
| 顶栏「模型图」/ Esc | 打开 / 关闭 |
| 滚轮 | 以光标为锚点缩放（0.15×~2.5×） |
| 拖空白处 | 平移（组与组之间那条缝；中键拖动在哪儿按都能平移） |
| **拖组标题条** | 整组连同成员卡片一起移动，**只动这一组**（组里其它地方不接拖动） |
| **拖空组的标题条** | 一样能拖：组里还没有表时，框的位置记在组的记录里（见 §8） |
| **空白处右键** | 打开表清单（从这里挑哪些表上图） |
| **单击卡片** | **只选中**（描一圈强调色），不关面板、不改 SQL |
| **双击卡片** / Enter / 卡片菜单「打开这张表」 | 关面板 + 打开这张表（和侧栏点表名同一个动作） |
| **拖卡片** | 摆位置；位移超过 4px 才算拖，松手落盘。**拖拽不改归属** |
| 卡片右上角 ⋯ | 移到某个分组 / 移出分组 / 新建分组并移入 / **从图上收起** |
| 组标题双击 | 就地改名（Enter 提交 / Esc 取消 / 失焦提交） |
| 点组色点 / 组菜单 | 弹出 **16 色马卡龙色板**，点哪个就是哪个（不再循环切换） |
| 组菜单 ⋯ | 重命名 / 换色 / 删除分组（成员回未分组） |
| **字段行右侧小圆点按住拖** | 拉一条关系：幽灵虚线跟随 → 目标**卡片**任意位置都可落、就近一行点亮 → 松手**直接建成 1 : 1**（基数随时点线改） |
| **鼠标移到连线上** | 飞线：一串小光点从**主键那一端**流向另一端（两端都不是主键就没有方向，只保留高亮） |
| **鼠标移到卡片上** | 这张表参与的**每条**连线一起跑飞线，同时高亮两端卡片 —— 一眼看出谁是数据源、谁在引用 |
| **点连线** | 改基数（1:1 / 1:N / M:N）、反向（仅 `1N`）、删除 |
| 状态栏「已收起 N 张」 | 打开表清单 |
| **+ 分组** | 新建空组，视口自动移过去 |
| 自动排列 | 清掉手工坐标（**包括空组的位置**）、回到自动布局；分组名、颜色、关系全保留 |
| 适应画布 | 缩放到刚好放下；上限 115%（表少时放太大反而空） |

### 7.1 拉线：为什么是「拖小圆点」而不是「拖卡片边缘」

**建关系只有拖小圆点这一条路**：曾经还有一个「+ 关系」弹窗（选表/列/基数），
两个入口维护两套校验，长的还是一条路走得多、另一条常年没人点。删掉之后，
唯一的入口就是把人教会一次的那个动作。

从卡片边缘拉线（v2 的做法）分不清「用户想连这张表还是这一列」，只能先建一条表级
关系再让用户去弹窗里补列 —— 两步操作，中间还容易放弃。

现在每行右侧有个小圆点（`.er-col-dot`），按住它就是按住**这一列**。
三层显隐：平时 `opacity .16`（不把每行变成表单），卡片悬停时 `.55`，行悬停时 `1`。

- 落点用 `document.elementFromPoint` 判断「鼠标底下是谁」，不自己算坐标 ——
  画布可能被缩放，DOM 命中测试永远和用户眼睛看到的一致；
- 但**不要求精确压在某一行上**：整张卡片都是落点，没压到行就取纵向最近的那一行
  （`erNearestColRow`），由行高亮告诉用户会连到哪一列。行只有 20px 高，缩小之后
  要瞄准太反人类 —— 标记仍然精确，只是不用瞄准；
- 起点那个圆点视觉 10px，用伪元素把**热区**撑到 **34 × 行高**（视觉不变）：它画在
  卡片右侧的内边距里，可点面积比看上去还小，手一抖就抓空。热区**往卡片内侧长**、
  不往外长 —— 卡片是 `overflow: hidden`，圆点右边到卡片边缘只剩 5px，往外长等于白长；
  高度**刚好一行**，高过行高就会压到隔壁行，变成「点这行、拉出下行的线」；
- 松手前再算一次落点：手快的时候最后一个 `pointermove` 可能还在路上；
- 幽灵线用和最终连线**同一套折线算法**，松手前就知道它会怎么绕。

### 7.2 默认建成 1 : 1，要改再点线

以前松手弹「四选一」（1:1 / 1:N / N:1 / M:N），理由是「默认值写进去就没人回头改」。
实际用下来这一步成本更高：每拉一条线都要多看一眼菜单，急着画结构的时候很烦，
而且四个选项里三个长得差不多，反而容易点错。

现在松手**直接按最保守的 1 : 1 建出来**，并 toast 提示「点这条线可以改基数」。
改的地方一点没少 —— 点连线，菜单里 `改成 1 : N` / `改成 M : N` / `反向` 都在。

为什么默认挑 1 : 1 而不是 1 : N：1 : 1 是「这两列一对一」这个**最弱的断言**，
错了顶多是少画了一个鸦爪；默认成 1 : N 则会在图上凭空断言「一对多」，
读图的人会当成已经确认过的事实。

### 7.3 收起一张表 vs 删掉它

「从图上收起」（`tables[id].hidden`）只影响这张画布：表还在库里、侧栏还在、
数据还在。跟它有关的关系整条不画（半条线没有意义，端点也不在画布上），
在表清单里会标「N 条关系不显示」，避免让人以为关系被删了。

放回来时**清掉旧坐标**，按自动布局落位 —— 留着旧坐标会直接压在别人身上。

入口只有两处：卡片菜单（收起）、状态栏「已收起 N 张」和空白处右键（放回）。
收起之后卡片不在画布上，也就点不到了，入口必须挂在别处。

### 7.4 点连线的坑

`erStage` 的 `pointerdown` 会对画布调 `setPointerCapture`。一旦捕获，后续 `click`
的 target 就变成 stage，连线的 `click` 监听永远收不到 —— 表现成「点线没反应」，
而且因为捕获了指针，连拖动都变诡异。所以在 `svg` 上单独拦一层：

```js
svg.addEventListener('pointerdown', ev => {
  if (ev.target.closest && ev.target.closest('.er-hit')) ev.stopPropagation();
});
```

连线本身 `pointer-events: none`，另铺一条宽的透明路径 `.er-hit` 接点击 ——
1.6px 的线谁也点不中。

### 7.5 归组只走菜单

不做拖拽归组。拖拽在小缩放、表多的时候很难落准，「拖到组框附近」的判定一旦猜错
就是表莫名换了组；菜单只有一次点击，不会猜。

**点选和拖卡片共用一个 pointer 序列**，在 `pointerup` 里按位移分流，不用 `click`：
拖动结束时浏览器照样补一个 `click`，两个行为抢同一个事件只能靠「刚才拖过没有」
这种标记区分，很容易漏复位 —— 表现成「拖完一张表，下一次点别的表没反应」。

单击只**选中**（描一圈 `--accent`），不进编辑：图是用来读结构的，点一下就关面板、
把编辑器里的 SQL 换成这张表，误触代价太大。进编辑有三条明确的路：双击卡片、
卡片菜单里的「打开这张表」、卡片聚焦后按 Enter。

拖动过程中只改卡片的 `left/top` 和组框尺寸，连线淡到 25% 不重算：每帧重建整张图
会丢 pointer capture，手一快就变成「拖到一半卡片卡住」。松手才 `erRender()` + 落盘。

最近拖过 / 改过的那一组排到最后画（`erHotGroup`）：DOM 顺序就是层级，卡片拖到
别组旁边时如果还沉在下面，会被别人的卡片盖住。

### 7.5.1 飞线：方向只能来自主键

鼠标压在连线上时，线上会跑一串小光点，**从主键那一端流向另一端** ——
一眼就能看出「这张表的这一列是数据源，那张表的那一列是引用」。

方向判定只有一条规则（`erFlowDir`）：一端是主键、另一端不是，就朝不是的那一端流；
两端都是主键、或者都不是，**没有方向，就不画飞线**，只保留原来的高亮。理由很直接 ——
两个普通列之间谁引用谁，图上根本没有依据，编一个方向比不画更糟。

实现上用一条和连线同几何的 `.er-flow` 路径 + `stroke-dasharray` 动画：

- 路径点按方向重排（`erEdgeGeom` 多返回一份 `pts`，反向时 `.reverse()`）——
  `stroke-dashoffset` 往负走就是沿路径正向流，所以只需要把折线反过来画；
- 两个触发口：压在这条线上用 CSS 相邻选择器 `.er-hit:hover + .er-flow`；
  压在**卡片**上由 `erHighlight()` 给这张表参与的每条飞线加 `.hot` ——
  后者复用已有的表格级高亮（它本来就在算「这张表参与哪些边」），所以鼠标移到
  卡片上时，线亮、两端卡片亮、飞线一起跑，一次动作三处反馈；
- **光点用亮度对比，不用色相**：悬停卡片时连线自己也会变成 `--accent` 的亮蓝线，
  同色的点压上去就糊成一条，只剩一圈光晕 —— 这是实测出来的「移到卡片上不如移到
  线上明显」。现在点用 `--text`（深色皮肤近白、浅色皮肤近深），再叠三层阴影：
  最里一圈近黑把点和底下的线隔开，外面两层 accent 做光晕；
- 光是**圆点**，不是短横条：`stroke-dasharray: 0 11` + `stroke-linecap: round` ——
  dash 长度取 0 时，圆头把这一笔画成一个直径等于线宽的圆点，间距由第二个值定。
  以前是 `7 11`（7px 的小长条），放大看像一串短横杠，不像「数据在流」；
  点径 3.2px 是量着缩放下限定的：再细在 70% 缩放下就只剩虚线感；
- **相位错开**：一张卡片几条线同时点亮时，全都从 0 起步就是「一起闪」，
  `animationDelay` 按序号负延迟错开（`-(i % 9) * 0.13s`），看着像几股数据各走各的；
- 光晕只在点亮时挂上：一条图可能上百条线，全都挂着 filter
  会让平移缩放多算一堆离屏合成；
- 系统开了「减少动态效果」时不跑动画，只留一条亮线。

### 7.6 拖整组：只有标题条是抓手

组框原来整块 `pointer-events: none`，只有标题条吃事件**而且不接拖动** —— 结果按住标题
拖什么都没发生；按住组里的空白拖，事件漏给 `erStage`，走的是**平移画布**，看起来就是
「拖一个分组，其他分组一起动」。

两个坑都要堵：

1. **漏事件** → 组框整块 `pointer-events: auto`。组里的空白把左键吃掉，什么也不做 ——
   漏下去就是平移，正是那个 bug。
2. **别整块都能拖** → 只有标题条（`.er-group-label`）起拖动，组里空白只吞不拖。

拖动实现：`erStartGroupDrag` 记下这一组每张卡片的起点，`erGroupDragMove` 按同一 Δ
（除以 `erView.zoom`）平移卡片和组框，4px 阈值内算点击；松手才
`erSnapshotCards()` + `erRender()` + `erSave()` —— 存**全量**坐标，因为这一组里
每张卡片都动了。

几个细节：

- 色点、`⋯` 按钮、改名输入框在 `pointerdown` 里 `stopPropagation`：它们是「点一下就
  完事」的按钮，不该先起一个拖动。
- 卡片压在组框上面（DOM 顺序在后），照旧自己接拖动，两种拖动不抢。
- **拖动过程不 `setPointerCapture`**，后续事件由 `document` 上的 pointermove/up 接。
  捕获会把鼠标事件重定向到组框，名字那个 span 上的 `dblclick`（双击改名）就再也
  收不到 —— 这个坑实测踩过一次。没有捕获就有「鼠标在窗口外松手」的问题，
  所以 `pointermove` 里先看一眼 `ev.buttons`，左键已经松了就当场收尾。

**空组怎么拖**：框是成员卡片的包围盒，一张表都没有时它没有任何可依附的东西，
位置必须记在组的记录里（`groups[].x/y`），否则松手一渲染就弹回自动布局 ——
表现成「这个组拖不走」。规则只有一句：**有成员时以卡片为准，这张坐标不参与**；
组清空之后也回到这里，而不是跳回全图末尾。第一个被移进来的表也落在这个框里
（`erPlaceModel` 用它当锚点），不会跑到别处去。

代价是组内空白不再是平移区，所以补了**中键拖动平移**（`button === 1`，压在任何卡片
或组框上都能用）；左键平移留给组与组之间那条缝。

组框吃起来以后跨组连线照样能点：连线层（`.er-edges`）在 DOM 里排在组框之后，
层级上在组框之上，只有 `.er-hit` 那条 14px 的透明热区吃事件。

## 8. 侧车文件

模型元数据放 `<数据目录>/diagram.json`，每个库一份（多库各自一套目录，天然隔离）。
**不进 catalog.json**（那是 schema 的唯一真相，会被 DDL / 备份 / 回收站 / PG 兼容层读），
**不进 localStorage**（换浏览器就丢，图属于库不属于浏览器）。

```json
{"version": 3,
 "groups": [{"id": "gmw27lf47lyd0", "name": "交易", "color": 2},
            {"id": "gmw2wsfbj5qy", "color": -1, "x": 474, "y": 45}],
 "tables": {"2": {"group": "gmw27lf47lyd0", "x": 62, "y": 48},
            "3": {"group": "gmw27lf47lyd0"},
            "7": {"hidden": true}},
 "links": [{"id": "m9x1", "from": {"table": 4, "columns": ["id"]},
            "to": {"table": 6, "columns": ["basis_id"]}, "card": "1N"}]}
```

几个关键约定：

- **`tables` 是「表拥有组」，不是「组拥有表」**。v1 的 `groups[].tables` 让成员改不动，
  v2 反过来：一张表一条记录，`group` 为空就是未分组。
- **坐标可以是 `null`**：表被移进某个分组但还没被拖过，这时它「有归属没位置」。
  用 0 代替会把卡片摞在画布左上角。半个坐标（只有 x）整条丢掉。
- **`color` 是 0..15 的数字**，直接对应 CSS 的 `g0..g15`，省一层名字映射。`-1` 表示
  「按顺序取」。色板是 16 个马卡龙色相（`--g-h` / `--g-s` / `--g-l` 三个变量），
  卡片标题栏、组底色、连线端点、拉线圆点全都从这三个变量算出来，换色板只改一处。
  「未分组」固定用最后一个（雾霭，中性色），不会和用户选的颜色撞。
- **`groups[].x/y` 只服务空组**：有成员的组，框是成员卡片的包围盒，这两个值不参与
  （留着是为了组清空之后回到最后待过的地方）。没有它们，新建的空组拖不动 ——
  位置每次渲染都由自动布局重算，松手就弹回去。校验规矩和卡片坐标一样：半个坐标
  或越界整条丢掉。
- **没有 `view`**：缩放和平移每次打开都重新适应画布，存了反而要处理「布局变了但
  视口没变」这种对不上的状态。
- **键是表 ID，不是表名**：RENAME 之后归属和位置要跟着那张表走。
- **`links[].id` 只是给前端按 id 找边用的**，不参与对账。关系靠「两端表+列」识别 ——
  它没有名字，也不该有。

### 8.1 迁移：v1 → v2 → v3

读到老版本自动转换，并把结果写回文件（否则每次打开都要重新折腾一遍）。

**v1 → v2**（`cards` → `tables`）：坐标照搬，`group` 留空；`groups[].tables` 铺平成
`tables[id].group`，同一张表被两组认领时**先到先得** —— 前端当年也是这么画的，
迁移必须和当年的显示一致。

**v2 → v3** 是这一次改动的核心，**两张表要换个位置**：

| v2 | v3 |
|---|---|
| `child` / `columns`（外键在子表上） | `to` / `to.columns` |
| `parent` / `refColumns` | `from` / `from.columns` |

v2 的 `card` 说的是「**子端**几个」，v3 的 `card` 说的是「**from 端**几个」。所以：

- `1N`（子端多）→ 把 **父表放到 from**，`{from: parent, to: child, card: '1N'}`
- `11` / `NM` → 两端对称，按 `{from: child, to: parent}` 搬过去即可

少翻这一次，每一条一对多都会画反 —— 一横跑到子表上，鸦爪跑到父表上，
而且因为「看起来也像条线」，没人第一眼能发现。

v2 的 `overrides`（改过的基数）、`hidden`（否认的边）在 v3 **整体丢弃**：
它们的主体是「库里那条外键」，而 v3 的图不承认外键的存在，没有可以挂靠的对象。
前端在这一版里也不再读取它们。

分派不看 `version` 号，看**形状**：`decodeLinks` 先试 `from`，有就是 v3；
否则试 `child`，有就是 v2。理由是老文件可能被手改过、version 号和内容对不上，
按形状分派不会因此把整张图读成空。

### 8.2 接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/diagram` | 读，按当前表**剪枝**后返回 |
| POST | `/api/diagram` | 整份覆盖（清洗 + 剪枝 + 原子写） |

**整份覆盖而不是增量**：一张图的坐标是相互关联的（拖走一张，旁边那张的位置才有
意义），增量更新反而要处理更多冲突。松手时前端把**所有**卡片坐标一次性存下来，
不是只存被拖的那张 —— 只记一张的话，剩下下次打开会按自动布局重排，等于拖了个寂寞。

读失败 / JSON 坏掉一律当「没有布局」：它是锦上添花的视图，不能让一个坏文件把整张图
变成打不开的错误页。写入走 `tmp + fsync + rename`（和配置文件同一套）。

进门先归一化，不信任何一条坐标：NaN / Inf / 超过 ±100000 会让画布撑到浏览器算不出来
的尺寸，表现成「打开就白屏」，比报错还难查。指向不存在的组一律归成未分组，不凭空造组。

归一化还会丢掉：两端列数不等的、缺表缺列的、同表同列自连的、`card` 不是三个合法值
（退回 `1N`）的、重复 id 的（留第一条）。

## 9. 生命周期

剪枝按**列**对账（`prune(cols map[int64]map[string]bool)`），这是 v3 的新要求：
关系挂在字段上，表还在但列没了，那条关系就该整条失效。

| 事件 | 行为 |
|---|---|
| RENAME TABLE | 原位不动（键是 ID） |
| RENAME COLUMN | 指向它的关系**整条剪掉**（不像 v2 只是基数退回推导值） |
| DROP COLUMN | 同上 |
| DROP TABLE | 坐标、参与的关系、收起记录一起清；**空组保留** |
| CREATE TABLE | 自动上图进未分组（`hidden` 不写就是显示）；手工摆过位的话，
新卡片按组内锚点排到下方一行 |
| 清空库 / 载入示例 | 同上，全部剪光，不需要专门清理 |

剪枝放在**读**的时候做，不挂在 DDL 上：DROP 的时候没人会想到去通知这张图，等下次
打开时按当前 catalog 对一遍账最省事，也不会让 DDL 多一条失败路径。

**空组不因为空了就删**。用户建了组还没放表，那也是设计意图；顺手删掉会让「新建
分组」看起来毫无反应。

## 10. 已知边界

- **物理图（第二阶段）没做**：不能从图生成 DDL，也不能显示库里的外键。
  这是刻意的顺序 —— 先把「图是源头」这条立住，再谈怎么落到库里。
- 关系只支持**单列**（结构上支持多列，UI 没有入口）。
- **一条关系不能落成外键**。要做的话得先解决「现有数据可能违反约束」的检查。
- 卡片最多显示 14 行字段，多了折成「还有 N 列」；卡片本身不能折叠。
- 表超过约 60 张会拥挤（分组、收起能缓解），没做分组折叠。
- 收起一张表会把它的所有关系一起藏起来，没有「只藏表、线还画着」这种中间态。
- 组内分层只看手画的关系，所以刚开始什么都没线时，组内按表名排。

## 11. 回归覆盖

`tools/ui_check.js` 里模型图一段 40 余条断言，用**真实鼠标**（`Input.dispatchMouseEvent`）
走完：清空侧车 → 打开 → 一张表一张卡片 → 未分组 → 自适应 → **库里 1 个外键、图上 0 条线**
→ 拉线提示 → 每行一个连接点 → **圆点热区（视觉 10px、往里可点 25px、不越行）** →
建组 / 改名 / 移表 / 换色 / 落盘 → 拖卡片 → 落盘 6/6 →
拖字段建关系（幽灵线 + 目标点亮 + **松手直接 1:1、不弹菜单**）→ 起点落在字段行中心 → 贴卡片边缘 →
圆角折线 → **连线不穿过别的卡片** → 1:1 两端各一横 → 飞线方向/悬停 → **画关系不改库** → 点线改 M:N →
重开还在 → 删关系 → 收起 / 表清单 / 复位 → 临时表剪枝 → 点卡片选中、双击才进编辑。

中心断言只有一句：

```js
check('模型图：库里写着外键，图上一条线也不画',
  demo.fk >= 1 && erUi.edges === 0, `库 ${demo.fk} 个外键 · 图 ${erUi.edges} 条线`);
```

它崩了，就说明有人又去读外键了。

三个坑写在这里，省得下次再踩：

- **位置断言必须按表名定位，不能拿「第一张卡片」**：拖完一张表之后 `erHotGroup`
  会把这组排到最后画（DOM 顺序变了），下一次 `querySelector` 拿到的是另一张表。
- **「卡片在组框里」不能用 DOM 包含关系判断**：卡片是画布上的绝对定位元素，
  **不在组框的 DOM 里**，`g.querySelector('.er-card')` 永远空。按包围盒判断。
- **落盘断言不能 `sleep` 固定毫秒**：`erSave` 有 300ms 防抖，点完立刻拉接口拿到的是
  上一版。用 `waitFor` 等「服务端真的存下了这个值」。

服务端 `web/diagram_test.go` 10 个用例：空文件、往返（含 `hidden`）、v1 迁移、
**v2 迁移（方向翻转 + overrides/hidden 丢弃）**、DROP 表剪枝、**DROP 列剪枝**、
坏数据归一化、**自连接保留**、空组保留、未知组引用。

## 12. 样例数据

示例库 `db/sample.go` 里有几条为了看图而设的链（这些外键**不会**出现在模型图上，
它们只是「库里有约束、图上没有线」这个断言的对照物）：

- `employees.dept_id REFERENCES departments(id)`
- `orders.employee_id → employees.id`、`order_items.order_id → orders.id`（三级链）
- `tags.article_id → articles.id`

跑回归用的那 6 张表（`er_basis` / `er_fact` 等）是 `ui_check.js` 自己造的临时表，
跑完就删 —— 不要指望在示例库里找到它们。截图是在跑完「4 张保留下来的表 + 5 条关系 +
2 个分组」那一步之后拍的，`diagram.json` 最后会被测试清回 `{"version": 3}`。
