建表与增删改查

          
最小闭环：建表 → 插数据 → 查 → 改 → 删。表建在 demo 上，不碰示例数据。

          
CREATE TABLEINSERTSELECTUPDATEDELETE

          
DROP TABLE IF EXISTS demo;
CREATE TABLE demo (id serial PRIMARY KEY, name text, n int);
INSERT INTO demo (name, n) VALUES ('a', 1), ('b', 2);
SELECT * FROM demo ORDER BY id;
UPDATE demo SET n = n + 1 WHERE name = 'a';
DELETE FROM demo WHERE name = 'b';

查询：筛选、排序、分页、去重

          
日常用得最多的一层，条件、排序、翻页、去重都在这里。

          
WHEREAND / OR / NOTINBETWEENLIKE / ILIKEIS NULLORDER BY ASC/DESC NULLS FIRST|LASTLIMIT / OFFSETDISTINCT

          
SELECT DISTINCT city FROM departments ORDER BY city;

SELECT name, salary FROM employees
WHERE salary BETWEEN 20000 AND 45000 AND name LIKE '%张%'
ORDER BY salary DESC
LIMIT 5;

        

      


      

        
3

        

          
分组统计

          
聚合函数配 GROUP BY；分组后再筛选用 HAVING（不是 WHERE）。

          
count / sum / avg / min / max（含 DISTINCT）· GROUP BYHAVING

          
SELECT dept_id, count(*) AS n, round(avg(salary), 2) AS avg_pay
FROM employees
GROUP BY dept_id
HAVING count(*) > 1
ORDER BY n DESC;

        

      


      

        
4

        

          
多表连接

          
LEFT JOIN 保留左表全部行，对不上的右表列为 NULL —— 统计「没人/没单」时靠它。

          
INNER / LEFT / RIGHT / CROSS JOINON表别名与列别名括号联接组 (a JOIN b ON …) x

          
SELECT d.name, count(e.id) AS n
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id
GROUP BY d.name
ORDER BY n DESC;

子查询与集合运算

          
标量子查询返回单值，可以引用外层列；WITH 把中间结果命名一次，多处复用。

          
标量子查询IN (子查询)EXISTSFROM 派生表 (SELECT …) xVALUES (…),(…)UNION [ALL] / INTERSECT / EXCEPTWITH

          
SELECT name FROM employees
WHERE dept_id IN (SELECT id FROM departments WHERE budget > 100000)
  AND salary > (SELECT avg(salary) FROM employees);

WITH big AS (SELECT id FROM departments WHERE budget > 100000)
SELECT count(*) FROM employees WHERE dept_id IN (SELECT id FROM big);

写入进阶：返回、冲突、批量

          
ON CONFLICT 是「有就改、没有就插」；RETURNING 直接拿到写后的行，省一次查询。写在 demo_up 上。

          
RETURNINGON CONFLICT DO NOTHING | DO UPDATE SET … EXCLUDEDINSERT … SELECTUPDATE … FROMDELETE … USING写语句的 WHERE/SET/VALUES 里也能用子查询

          
DROP TABLE IF EXISTS demo_up;
CREATE TABLE demo_up (id int PRIMARY KEY, name text, salary numeric(10,2));

INSERT INTO demo_up VALUES (1, '张伟', 42000)
ON CONFLICT (id) DO UPDATE SET salary = EXCLUDED.salary
RETURNING id, name, salary;

UPDATE demo_up d SET salary = s.salary
FROM (VALUES (1, 50000)) s(id, salary)
WHERE d.id = s.id
RETURNING d.id, d.salary;

事务与并发

          
表级 S/X 锁、严格两阶段封锁（可串行化）；SAVEPOINT 用于部分回滚，ORM 的嵌套事务靠它。演示在 demo_tx 上。

          
BEGIN / START TRANSACTION（ISOLATION LEVEL …、READ ONLY）· COMMITROLLBACKSAVEPOINT / ROLLBACK TO SAVEPOINT / RELEASE SAVEPOINT

          
DROP TABLE IF EXISTS demo_tx;
CREATE TABLE demo_tx (id int PRIMARY KEY, v int);
INSERT INTO demo_tx VALUES (1, 100), (2, 200);

BEGIN;
UPDATE demo_tx SET v = v + 1 WHERE id = 1;
SAVEPOINT sp1;
DELETE FROM demo_tx WHERE id = 2;
ROLLBACK TO SAVEPOINT sp1;   -- 只撤销上面那条 DELETE
COMMIT;

SELECT * FROM demo_tx ORDER BY id;

字符串 lower / upper / length / trim / lpad / rpad / replace / substring / position / concat / string_agg日期 extract / date_part / date_trunc / now · INTERVAL '1 day' 与时间加减序列 nextval / currval / lastval其他 coalesce / nullif / greatest / least / random / regexp_matches / unnest类型 int / bigint / serial / numeric(p,s) / real / double precision / text / varchar(n) / boolean / date / timestamp / interval / vector(n)

          
SELECT extract(year FROM now()) AS y,
       date_trunc('month', now()) AS m,
       lpad('1', 6, '0') AS code,

10

        

          
向量检索（VECTOR）

          
存 embedding、按相似度取前 K 条。维度必须写死（vector(3)），值写成 '[0.1,0.2,…]'；检索只有一种写法：按距离排序 + LIMIT。

            没有近似索引，距离是逐行算的（会分给多个核）：10 万行 × 128 维取最近 10 条约 15 毫秒，
            100 万行约 0.35 秒 —— 时间花在逐行取数和算距离上，不在排序。

          
VECTOR(n)（1 ≤ n ≤ 4096，省略维度会报错）<-> 欧氏距离<=> 余弦距离<#> 负内积距离可出现在 SELECT / WHERE / ORDER BY

          
DROP TABLE IF EXISTS demo_vec;
CREATE TABLE demo_vec (id int PRIMARY KEY, title text, v vector(3));
INSERT INTO demo_vec VALUES (1,'甲','[1,0,0]'), (2,'乙','[0,1,0]'), (3,'丙','[0.9,0.1,0]');

-- Top-K：距离越小越像；1 - 余弦距离 就是相似度分数
SELECT id, title, 1 - (v <=> '[1,0,0]') AS score
FROM demo_vec
ORDER BY v <=> '[1,0,0]'
LIMIT 3;

-- 也可以先按距离筛一遍，再按别的列排序
SELECT id, title FROM demo_vec
WHERE v <-> '[1,0,0]' < 0.5
ORDER BY id;

-- 示例库里已经有一张 articles（9 篇文档 × 8 维，四类主题），打开就能试：
SELECT title, 1 - (embedding <=> '[0.9,0.08,0.02,0,0.05,0.1,0.02,0.01]') AS score
FROM articles
ORDER BY embedding <=> '[0.9,0.08,0.02,0,0.05,0.1,0.02,0.01]'
LIMIT 3;

          

            三个算子怎么选（都满足「越小越像」，所以 ORDER BY 一律升序）：

            · <=> 余弦距离 = 1 − cos，只看方向、不看长度。embedding 基本都用它；
            1 - (v <=> q) 就是余弦相似度（0～1，越大越像），和向量有没有归一化无关。

            · <-> 欧氏距离，看绝对位置。数值尺度差别大（如图像特征）时更合适；
            向量没归一化时它和余弦给出的排序会不一样。

            · <#> 负内积 = −(a·b)（所以是负数）。只想按「热度 × 相似」排序、
            不希望被长度开方削平的时候用它；要看真实内积写 -(v <#> '[…]')。
          

          

            灌数据：一条 INSERT … VALUES 写多行最快 —— 每条约 1000 行（≈700KB）
            是甜点，再大单条语句的解析时间喧宾夺主，再小全是往返开销。10 万行 × 128 维灌完几秒、
            占 51MB 的 .vec。

            查询向量的维度必须与列定义一致，差一个数就报
            vector dimension mismatch: column is 128, value has 127。
            批量导入时先 CREATE TABLE … vector(128) 定好维度，再按同一维度生成文本。
          

          

            向量既没有「相等」也没有「大小」，下面这些写法会直接报错 —— 不是没做好，而是没有正确的答案：
            v = '[…]'、ORDER BY v、SELECT DISTINCT v、
            GROUP BY v、COUNT(DISTINCT v)、MIN / MAX(v)、
            JOIN … ON a.v = b.v、UNION / INTERSECT / EXCEPT、
            以及任何「把向量当文本」的写法（v || '…'、lower(v)、concat(v)、
            length(v)、string_agg(v, ',')、v::text）
            （UNION ALL 不受限），以及向量列上的 CREATE INDEX /
            PRIMARY KEY / UNIQUE。

            原因很实在：向量的真实数据在表的 .vec 文件里，行内只留一个槽位引用，而槽位每次写入、
            每次更新都会换。拿它判重，内容相同的两行会被算成两行、内容不同的两行可能被算成一行，
            而且结果看上去是正常的 —— 宁可直接报错，也不给这种答案。

            要按内容去重只能在应用侧做：单独 SELECT v 出来就是 '[0.1,0.2,…]' 文本，
            自己比字符串即可 —— 但也只有这一条路，库内没有把向量转成文本的函数。

            空间上还有一条要知道：向量存在 tables/*.vec 里，删行只把槽位放回空闲表，
            文件不会变小（VACUUM FULL 也不回收），所以它停在高水位而不是当前行数。

            客户端看到的是 text：vector 没有注册类型 OID，所以结果、information_schema、
            pg_attribute 里都按 text 出现。用「读元数据生成 DDL」的工具改表要当心：
            把这一列改成别的类型会被拒绝（cannot cast a stored vector to text），数据不会丢，
            但它也不会按你的预期变形。

诊断与维护

          
看计划、看落盘、看系统目录；EXPLAIN ANALYZE 会真的执行并给出每步行数与耗时。

          
EXPLAINEXPLAIN ANALYZECHECKPOINT / FLUSHVACUUM [表]VACUUM FULL [表]ANALYZESHOW / SET statement_timeoutCOPY … FROM STDIN / TO STDOUT系统目录 pg_catalog / information_schemapg_database_size / pg_size_pretty监控 pg_stat_database / pg_stat_user_tables / pg_stat_user_indexes / pg_stats

          
EXPLAIN ANALYZE SELECT * FROM employees WHERE dept_id = 1;
SET statement_timeout = 30s;   -- 每条语句最多跑 30 秒（0 = 不限）
SHOW statement_timeout;       -- 回显当前值：30s / 1min / 0
SHOW server_version;
ANALYZE;
CHECKPOINT;
VACUUM employees;        -- 整理页内空洞、回收尾部空页（不动大字段）
VACUUM FULL employees;   -- 整份重写：连大字段里 UPDATE 留下的旧正文一起收掉
SELECT pg_size_pretty(pg_database_size(current_database()));

          

            让跑飞的查询自己停下来：SET statement_timeout = 30s 之后，每条语句跑到
            30 秒就被中断（SQLSTATE 57014，事务按普通错误回滚）。没有它，一个写错的连接条件
            能占着 CPU 好几分钟，只能等人去 Kill —— 现在 Kill 也会在下一个检查点（每 1024 行）立刻停，
            不用等整条跑完。

            写法：SET statement_timeout = 500ms / 30s / 2min；
            0 关掉；SHOW statement_timeout 回显当前值；RESET 恢复默认（不限）。

            裸数字按秒（30 = 30 秒），这一点和 PostgreSQL 不同 —— PG 的裸数字是毫秒，
            要毫秒在这里写 30000ms。设置只对当前连接有效：客户端重连、或连接池还池时
            发 DISCARD ALL，都会回到「不限」。
